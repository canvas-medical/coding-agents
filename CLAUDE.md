# coding-agents

Guidance for changing the plugins in this marketplace. `canvas-plugin-assistant/CLAUDE.md` is for the plugin code CPA generates, not for CPA itself.


## canvas-plugin-assistant (AKA CPA)
- Studio's image (from canvas-medical/studio) clones this repo's `main` at build time, so a merged CPA change reaches Studio with no pin or review gate.
- Studio names CPA's MCP tools (`session.py`, `project_boundary.py`) and `/cpa:` skills and commands (`prompts.py`). Before changing one of those names or a tool's arguments, `git grep` Studio's `origin/development` for it; a needed Studio change must merge immediately following a CPA update.
- Bump `version` in both `canvas-plugin-assistant/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`.
- Route on exit codes, files, or an MCP tool's `Status:` line, never on CLI free text. Every tool outcome ends with a `Status:` line and has a `TestStatusLine` case.
- Cite canvas-plugins `canvas_cli/apps/platform/` file:line for any claim about `canvas` CLI behavior.
- A plugin is deployed one of two ways, and prose covers both: as its own repository (the `canvas init` layout), or from inside a larger repository with `canvas deploy --snapshot` (canvas 0.262.0+), which the `deployer` tool picks itself from `git rev-parse --show-toplevel`.
- `*_context.txt` files under `skills/canvas-sdk`, `skills/fhir-api-client-development`, and `skills/canvas-platform` are regenerated by workflows; don't hand-edit them.
- Pass `--cov=<module name>` to pytest, not a file path.
